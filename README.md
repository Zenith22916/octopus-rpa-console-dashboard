# 八爪鱼 RPA 触发器 & 运行记录仪表盘（octopus-rpa-console-dashboard）

抓取八爪鱼 RPA 企业管理台的机器人触发器和运行记录，**前后端分离**的局域网单页仪表盘：

- **运行数据分析**：概览指标 + 触发/状态分布 + 星期×小时热力图 + 各机器人排队与负载 + 失败看板
- **任务时间轴**：每台机器人的真实运行记录（手动 / 定时 / Webhook），排队与执行两段彩色区分
- **运行记录详情**：单条记录完整信息、局域网共享日志目录检索、Monaco 只读查看器（VSCode 同款高亮/minimap）、异常高亮与搜索、选择机器人后重新运行
- **项目控制台**：云端项目列表 + 项目详情 + 选择机器人运行 + 飞书配置中心在线编辑
- **触发器排期**：触发器每周/每月循环任务时刻表（行=时刻、列=周几的表格；点应用标签直达项目控制台运行记录）
- **机器人状态**（运行监控）：一个机器人一张卡片（横屏一行 3 张 / 竖屏一行 1 张），看每台在跑什么、排队/空闲多久、近 24 小时与近 7 天负载

## 快速开始

```bash
# 1. 环境：Python 3.9+
pip install -r requirements.txt          # requests（抓取）+ openpyxl（整理时刻表）+ pymysql（MySQL，可选）

# 2. 配置：复制模板并填入账号密码
cp config.example.json config.json

# 3. 启动：双击 start_server.bat（Linux/macOS 用 ./start_server.sh；只要起服务就 python local_server.py）
```

浏览器打开 `http://localhost:8000`；局域网其他电脑用 `http://<本机IP>:8000`。

> 首次运行若提示缺少 `requests`，两个一键脚本都会自动 `pip install`（找不到 Python 则报错退出）。

**MySQL 持久化（可选）**：config.json 加 `mysql` 段即启用，运行记录幂等 upsert 进
`rpa_runs` 表（主键 `process_no`；在途记录 8 秒先行入库，跑完的终态由 60 秒抓取覆盖；
时间存毫秒时间戳 + 北京时间 `start_dt`），未配置/连接失败时静默跳过、不影响任何功能。
建库建表在服务器启动时自动完成（也可手动 `python db.py init`，`python db.py stats` 查行数）：

```json
"mysql": { "host": "127.0.0.1", "port": 3306, "user": "root", "password": "", "database": "octopus_rpa" }
```

## 架构

前后端分离（同项目目录），**MySQL 是唯一真相源**（表 `rpa_runs` 运行记录 + `rpa_triggers` 触发器排期）：

```
crawler.py ──网页版爬取──▶ MySQL（触发器排期；CSV 只留一份离线快照）
octo_api.py ──▶ 八爪鱼桌面 API（登录/项目列表/机器人清单/触发运行/运行记录）
dashboard.py ──▶ 数据聚合（build_schedule_payload 等；机器人状态已移到前端现算）
feishu_cfg.py ─▶ 飞书多维表格配置中心读写
xlsx_writer.py ─▶ xlsx 生成（纯标准库拼 zip + XML，支持合并单元格与着色，内存生成不落盘）
db.py ──▶ MySQL 持久层（幂等 upsert + 增量查询；记录带 updated_ms 最后修改时间戳）
                        │
local_server.py ──▶ 只有三个数据接口，其余按需
    ├─ records_poller   每 6s：桌面 API runningRecords 最新 50 条 upsert 入库；
    │                   **有实际变更才广播**（无变化零广播、零流量）
    ├─ trigger_poller   每 12h：网页版抓触发器排期入库（+ 排期页「立刻更新」手动触发）
    ├─ SSE /api/events  有变更通知前端「该来拉了」；每 20s 命名心跳保活
    └─ 启动时抓一轮排期（运行记录由 6s 轮询自动补齐）
                        │
web/（纯前端，hash 路由五视图）
    index.html + app.js + style.css + theme.css + mobile.css + theme.js + fonts/
    #/analysis（默认主页） #/timeline #/detail?id= #/schedule #/projects #/botstatus
    # 版面：左侧固定导航栏（品牌 + 两个分组导航 + 数据时间）+ 右侧主内容区
    # 桌面端（>880px）：theme.js 按窗口高度等比缩放 --s，所有内容压进一屏、不出原生滚动条
    # 手机端（≤880px）：mobile.css 整体换一套布局，自然文档流 + 整页滚动（详见「手机端适配」）
    # theme.css 为视觉增强层（配色/质感/动效/字体），删掉 index.html 里的引用即可回退原样式
    # mobile.css 为手机端布局层，删掉引用即回到桌面那套窄屏表现
```

### 数据同步机制

全站只有**一条**同步链路，与「当前在哪个页面」无关：

| 环节 | 做法 |
|---|---|
| 首次加载 | 拉一次最近 **7 天**运行记录（`/api/runs?days=7`），响应带回**快照游标** `cursor` |
| 变更通知 | 后端库有变更 → SSE 推 `event: change`（不带数据，只有通知） |
| 增量拉取 | 前端带上次的 `cursor` 请求 `/api/runs?cursor=…`，后端只回「`updated_ms` > 游标」的行，按 id 合并 |
| 游标来源 | **服务端在查询之前取的时间戳**，避免浏览器与服务器时钟差导致漏拉/重复拉 |
| 心跳与看门狗 | 后端每 20s 发命名事件 `event: ping`（**不是**注释行——注释行不会到达 JS，前端无法感知连接活性）。前端 60s 内没收到任何消息即判定连接假死，主动重连并补拉 |
| 切后台/锁屏 | 回前台时 `visibilitychange` 重置看门狗基准、检查连接、当场补拉增量 |
| 排期（触发器） | 不在这条链路上：12h 才变一次，**打开排期页拉一次**；要立刻更新用页内「立刻更新」按钮（后端同步抓完才返回） |

> 时间轴「数据范围」选到超过 7 天时（最长 4 周），前端会自动往前补拉缺失的那段。

### 省流量设计（内网穿透场景）

| 机制 | 说明 |
|---|---|
| 静态资源长缓存 | js/css/图片一律 `Cache-Control: public, max-age=31536000, immutable`，版本号由服务器按文件 mtime 自动注入（index.html 写 `?v=auto`，`_serve_index` 实时替换成 `?v=<mtime>`）——文件一改 URL 即变、缓存自动失效，无需手动 bump；二次打开页面**零下载** |
| 无变更零广播 | 6s 轮询的 upsert 逐行判断 `rowcount`，只有**真有行变化**才广播（重放同样的数据不算），空闲时后端一个字节都不发 |
| 只推信号不推数据 | `/api/events` 只推「有变更」这一件事（不带数据本体），前端凭自己的游标来问 |
| 时间戳增量拉取 | 前端带 `cursor` 请求，后端只回「最后修改时间 > 游标」的行——1 条记录变化就只传 1 条 |
| 命名心跳 + 看门狗 | 心跳是命名事件（20s 一次，约 30 字节）；前端 60s 无消息才重连，**正常时零额外请求** |
| gzip 压缩 | JSON 接口对 >1KB 的响应按请求 `Accept-Encoding: gzip` 压缩（记录列表压缩率约 80~90%） |

## 一键启动

Windows 用 `start_server.bat`、Linux/macOS 用 `start_server.sh`，两者就是**一行 python 启动命令**：

```bat
@echo off
title RPA Dashboard Server
cd /d "%~dp0"
python core\local_server.py
pause
```

- 数据更新全部由 `local_server.py` 内部完成：启动先抓一轮触发器排期，之后每 6 秒轮询桌面 API
  运行记录（有变化才入库+广播）、每 12 小时抓一次排期。无需任务计划。
- **`pause` 别删**：Python 启动报错时窗口会停住显示错误，而不是一闪而过。
- `python` 不在 PATH 时，把 bat 最后一行换成 python.exe 完整路径（或装 py launcher 用 `py -3`）。
- 端口 8000 被占用时直接报 `OSError: [Errno 98/10048] address already in use`——
  先关掉旧的 local_server 再启动；换端口改 `local_server.py` 的 `PORT` 一处即可。
- `.sh` 用 `python3`、必须 LF 换行；`.bat` 必须 CRLF 且纯 ASCII（`.gitattributes` 已锁定）。
- MySQL 是唯一真相源（`rpa_runs` + `rpa_triggers` 两张表），网页通过 JSON API 动态渲染、详情页按需拉取。
- 启动横幅会输出本机局域网 IP；关窗（或 Ctrl+C）即停止。

## 五个视图

> 侧栏按「看现状 / 改配置」分两组：
> **运行监控**（运行数据分析 / 任务时间轴 / 机器人状态）——现在与最近跑得怎么样；
> **配置管理**（触发器排期 / 项目控制台）——排期怎么设、项目配置与手动运行。
> 运行记录详情由链接进入，不在导航里。

### 运行数据分析（`#/analysis`，默认主页）

- 8 个概览指标卡：总运行数、成功率、失败数、运行中、平均排队、平均运行、最长单次、并发峰值（统计口径为全部已抓取记录，全量抓取后约 30 天）
- 触发方式分布、状态分布 两个饼图
- 星期 × 小时 热力图（找出运行高峰时段）
- 各机器人平均排队时长条形图 + 机器人负载榜（记录数/失败/失败率/平均排队/平均运行，失败率 ≥20% 标红）
- 失败记录看板，支持「导出失败记录 CSV」（带 BOM，Excel 直接打开不乱码）

### 任务时间轴（`#/timeline`）

> **桌面端是甘特图，手机端只有记录流** —— 两端策略完全不同，见下面各自的段落。
> 手机端把甘特图与筛选整块砍掉（`mobile.css` 里 `#tlFilter` / `#tlChartCard` 隐藏，
> `tlInit` 在手机端直接返回、不建 ECharts 实例）：390px 宽的甘特图，
> 无论转置还是压成缩略图，都读不出「运行顺序 + 时长」，不如把这一屏全给记录流。

#### 桌面端（甘特图 + 表格）

- **竖轴 = 机器人**（同一机器人时间重叠的记录自动分多行泳道堆叠），**横轴 = 时间**（右缘=当前时刻，内容随时间缓慢左移）
- **横轴刻度只读时间（`HH:mm`），日期交给两端的日期角标**：窗口左右边界顶部各标一个 `MM-dd`（左端左对齐、右端右对齐，与刻度同一行、同一基线）；刻度文字若会压到角标就不显示（按文字实际宽度判定保留带）。跨天时，**午夜那一格刻度直接把 `00:00` 换成日期**（`08-15`），因为午夜正是天与天的分界
- **网格线横竖同色**（`rgba(255,255,255,0.15)`），方向靠虚实区分：**时间刻度竖线是虚线**（背景参考）、**泳道分组分隔线是横实线**（谁属于哪台机器人的结构边界）
- **数据拆分**：每条记录按「排队（蓝）→ 执行（状态色）」两段区分，整条用白色边框框起；块内文字单行居中、过长截断加 `...`，少于 8 字不显示
- **极短记录不会被吞掉**：6 秒的记录在 6 小时窗口里只有 0.1px，原来按「不足 2px 不画」直接消失。现在以真实位置为中心撑到 4px 再画（只影响画出来的宽度，**不影响时长读数、拖动换算与点击跳转**，那些都按真实值走）。泳道分配仍按真实时间重叠算，与窗口大小无关，所以 7 天/30 天窗口下泳道数不会膨胀
- **筛选独立成卡片**：时间窗口 / 触发方式 / 显示排队 单独一张卡（原先贴在甘特图卡片顶部，和图表混在一起）
- **时间窗口**：下拉档位 30 分钟 ~ 7 天（默认 2 小时；窄高窗口自动改为 6 小时，横向更舒展）；Ctrl+滚轮可自由缩放到 10 分钟 ~ 30 天，下拉会自动留空表示「自定义窗口」
- **触发方式筛选**：全部 / 手动 / 定时触发器 / Webhook
- **直接拖动平移**：在图表上按住拖动即可平移时间轴，1:1 跟手（整幅长度 = 整个窗口宽度）；内容跟着手走（左=更晚、右=更早），拖到「现在」或最早数据处自动停住
- **底部窗口指示条**：滑块宽度 = 当前窗口占全部数据的比例（窗口越长滑块越宽），拖滑块或点轨道空白可平移；它只是指示器，窗口长度不能靠拖它改
- **缩放窗口**：`Ctrl/⌘ + 滚轮` 以鼠标所指时刻为锚点缩放（向上放大、向下缩小，范围 10 分钟 ~ 30 天）；也可用上方「窗口」下拉，或双击恢复默认
- 滚轮：向下 = 向未来（最多到"现在"），向上 = 向过去；双击图表：恢复实时跟随
- 「横向手势归平移、纵向仍可滚页面」；拖动后那一下不会误触发「点块进详情」
- 所有状态的数据块（含运行中）点击均可跳转详情查看日志
- **运行记录**：六列表格（机器人/应用/状态/开始/结束/用时），点某行让甘特图右边缘对齐该条记录的结束时间

#### 手机端（≤880px，纯记录流）

- **没有甘特图、没有筛选**：整屏就是一列运行记录，按**结束时间倒序**（最新跑完的在最上面；还在跑的 `end` 为空，永远置顶）
- **每张卡片**：左侧序号 + 应用名 + **右侧大号时长**（按状态着色）+ 机器人短名/状态/起止时刻/排队时长 + 底部一条按时长比例画的横条（谁长谁短不用读数字就能比出来）
- **日期分隔条**：跨天时插一条 `10-10` 的药丸，吸顶在导航下方，长列表里随时知道当前是哪天
- **动态无感翻页（两层）**：
  - **续批**：首屏 20 条，滚到底自动追加下一批（`IntersectionObserver` 盯底部哨兵，`rootMargin: 300px` 提前加载），底部显示「向下滚动加载更多… / 已到底 · 共 N 条」
  - **更新不跳位**：同步拉到新记录时，如果用户**还在顶部**就直接刷新；**已经滚下去了则一律不动 DOM**，只在屏幕底部浮一个「↑ N 条新记录」的药丸，点它才回顶部看新的 —— 正在看第 40 条时被新数据顶掉视线是最恼人的
  - 「进行中」记录的时长每 5 秒走一格，**只改那几行的文本**（`tlFeedTick`），不重排列表
- **点卡片直接进该条记录的日志详情**（没有甘特图要对齐，不需要「先对齐再点」两步）
- 标题栏四张指标卡（Webhook/手动/定时/机器人）在手机端按**全部记录**统计（没有时间窗口的概念）

### 运行记录详情（`#/detail?id=`）

- 左侧基础信息卡：机器人、状态、触发方式、触发器、流程 ID（flow_id）、流程编号（process_no）、起止时间、开始运行、排队/运行时长
- 顶部按钮：**↻ 重新运行**（**先弹窗选择执行机器人**，再调用 `/api/rerun`，返回批次号与执行机器人）、**⚙ 项目配置**（跳转 `#/projects?fid=` 并选中该项目）、**← 返回上一页**（无历史兜底回时间轴）
  - 弹窗数据来自 `/api/bots?flow_id=`，分三组：**本流程运行过的机器人**（默认选中最近一次成功运行的那台，带「推荐」标）、**在线可用的其他机器人**、**离线 / 已停用机器人**（默认收起）；另有「不指定，由平台分配」项
- 右侧日志内容卡：工具栏（异常数、搜索、上一处/下一处/仅看异常/**复制路径**）+ 多文件标签栏（大小/行数）
  - **↻ 刷新**（在「日志内容」标题右侧）：只看当前选中日志文件的**内容**，不必退出重进详情页——看实时日志时最常用
    - 实现是「重读文件」而不是「重建页面」：以已加载行数为偏移请求一页（`/api/log?...&refresh=1`），服务端顺带回一个锚点行（第 N 行原文）与当前总行数
    - 锚点行与本地最后一行一致 → 文件只是尾部追加，新行**增量接到 Monaco 模型末尾**，**滚动位置、搜索关键词、仅看异常、折叠状态全部保留**；有关键词时顺带把新行里的命中补上高亮
    - 锚点行不一致（文件被重写/轮转）→ 自动**整段重载**该文件并尽量停在原视口位置，避免新旧内容错接
    - 没有新内容时提示「已是最新（共 N 行）」；刷新中按钮图标转圈，请求结束自动恢复
    - 只影响当前标签对应的文件，其他文件的已加载内容与标签状态都不动
  - **复制路径**：一键把**当前选中日志文件**的完整共享路径（如 `\\SX-03\Logs\20260908\135111-…\135111-….log`）写进剪贴板，粘到资源管理器地址栏即可打开；切日志标签时复制目标跟着变
    - 成功反馈只把按钮**染绿 1.4 秒**（不改文案、不改尺寸），完整路径以屏幕底部轻提示回显
    - 局域网访问（`http://<IP>:8000`）不是安全上下文、`navigator.clipboard` 不可用，自动回落到 `textarea + execCommand`；两种方式都失败时提示手动复制
    - 共享目录未连上 / 文件清单读不出来时，退回复制该记录的**日志目录**并在提示里说明（该场景仍能复制）
- 日志来自**局域网共享 UNC 目录**（`config.json` -> `robot_logs` 白名单）
- **Monaco 只读日志查看器**（VSCode 编辑器内核，`assets/monaco/` 离线自托管）：
  - **按八爪鱼日志的固定格式逐段着色**（格式：`级别 时间戳 【子流程】第N行【指令】：内容`）：
    - 行首级别：错误红 / 警告橙 / 消息灰；时间戳灰蓝
    - `【子流程名】` 蓝、`【指令类型】` 青绿（靠后文「第N行」自动区分）
    - `生成变量 变量名` 中的变量名浅蓝；文件路径（盘符/UNC）淡蓝
  - **结构化内容识别**：字典键名浅蓝、字符串值橙、true/false/null 蓝字（对齐 VSCode JSON 配色），花括号与列表方括号灰蓝、元素逐个着色
  - **避免误标**：`已启用异常监控`、`超时[2228/180000]`（等待静默的进度计数）这类含级别词但非异常的内容不着色
  - 内置 minimap 缩略图 + 概览标尺（错误/警告行红/橙刻度）
  - **超长行自动折叠**：换行后超过 3 个显示行的日志默认收起（只保留约 3 行预览 + 「⋯ 已折叠」提示条），点击**最左行号**或行首 ▸ 箭头展开/收起；搜索时含关键词的折叠行自动展开，异常统计按原文判定不受折叠影响
  - 多文件以标签页切换，单编辑器多模型，切换零重建
- **大日志分段加载**：首段 5000 行，「加载更多」按行增量追加（不重置滚动位置）

### 触发器排期（`#/schedule`）

- **表格版式**：行 = 执行时刻，列 = 周几（每月视图为当月有任务的日期），格子内直接列出该时刻要跑的应用标签
  （取代早期的 ECharts 甘特图：行高固定不再互相挤压、应用名完整可读、天然可搜索与横向滚动；「时刻」列粘左侧）
- 视图切换：每周 / 每月；筛选：机器人（含「所有硕晞」「所有宝实」快捷分组 + 单机器人）、状态（已启用/已停用/全部，默认已启用）
- 指标卡：触发器总数 / 已启用 / 已停用 / Webhook；标题右侧显示「N 个时刻 · M 个排期点」
- 按应用配色（12 色），同色 = 同一应用；悬停某个标签会点亮全表同一应用的全部标签（其余淡出）
- **当前时刻标记**：今天那一列加淡红底色 + 一条当前时刻的红色虚线横线（线尾带 `HH:MM` 标签），每 10 秒跟随一次；两者都画在应用标签**下面**，不遮挡标签文字（横线在标签行内穿过时会被标签盖住）
  - 每月视图下，若今天不在「有排期的日期」列里，则只画横线、不标底色（没有对应列可标）
- **点击应用标签 → 跳转项目控制台并直接打开该项目的「运行记录」tab**（深链 `#/projects?fid=<flowId>&tab=runs`，flowId 来自排期表 `rpa_triggers` 的 `flow_id` 列）
- 同一时刻同一应用跑在多台机器人上时，标签右上角标 `×N`，悬停提示里列出全部机器人
- **立刻更新**（「导出 Excel」左侧）：点一下立刻从八爪鱼云端抓取最新触发器并写库，**抓完才返回**，期间显示转圈提示，返回后本页自动刷新；结果提示「已更新 N 条触发器」或「排期无变化」。
  排期平日由后端每 12 小时自动抓一次，这个按钮用于「刚改完排期想马上看到」的场景
- **导出 Excel**：按当前筛选（视图 + 机器人 + 状态）生成 xlsx 并触发下载，三张表（首表为日历）——
  - `排期日历`：保留原甘特图版式（导出侧未改）。行 = 时刻 × 应用，列 = 周几（月视图为当月有排期的日期）；同一应用在该时刻的排期日**合并成一个色块**（跨机器人合并，颜色取调色板，灰色 = 已停用），「时刻」列在同一时刻的多行之间纵向合并，空白格保留边框
  - `排期明细`：与表格同口径展开的排期点（周视图按周几、月视图按日期），含触发器名/触发方式/周期类型/状态/更新时间
  - `触发器汇总`：命中筛选的全部触发器（含 Webhook 与未排期项），比表格多一列「排期描述」（如「每周周一 08:00」）
  - 说明：页面表格不合并色块，逐格列出应用；日历表只在**日期连续**时才并成一块，避免色块横跨没排期的日期
  - xlsx 由后端内存生成（不落盘），下载文件名带上视图/机器人/状态与日期

### 项目控制台（`#/projects`）

- **标题栏指标卡**：项目总数 / 已配映射 / 未配映射 / 配置组数（映射 = 该项目是否已关联配置组，加载失败或列表为空时自动清空）
- 左侧全项目列表（八爪鱼云端 flows），可按「修改时间 / 名称」排序、手动刷新；项目名首字带色块（宝蓝/硕绿/国橙/泇紫/财金等固定映射，其余按首字取色，X 固定灰）
- 右侧详情：项目名、flowId、更新时间、负责人；标题行右侧 tab（飞书配置 / 运行记录）+「▶ 运行该应用」按钮
- **运行控制**：「▶ 运行该应用」先弹窗选择执行机器人（默认选中该项目最近一次成功运行的机器人），也可选「不指定，由平台分配」；指定机器人可避免被平台分配到无权限机器人报「没有操作权限」

  - 项目 ↔ 配置组映射（存配置中心 `group=project` 组，key=`p.<flowId>`），「保存映射」后自动加载
  - 配置表格含 key / value / type / desc，json 类型展示时自动排版；「编辑」或「＋ 新增配置」在弹窗中修改
  - 弹窗：编辑时 key 锁定、type 下拉（string/number/bool/json）、bool 开关、json 自动格式化；desc 保存时去除换行

  - 列表/配置/运行记录加载时显示全屏半透明遮罩，防止加载中误操作

### 机器人状态（`#/botstatus`，运行监控）

- **一个机器人一张卡片**的网格，按「运行中 → 排队中 → 空闲，近 7 天记录数降序」排列
  - 列数只看宽高比：**横屏一行 3 张、竖屏一行 1 张**；卡片多了在容器内往下滚动（桌面 70vh、手机整页滚动）
  - 卡片 = 顶部「状态点 + 机器人名 + 状态标签」/ 中部「任务名 + 进度」两行 / 底部 6 个读数（3 列 × 2 行）；左缘色条与状态标签同色，扫一列卡片就知道哪几台在跑
  - **所有卡片尺寸严格一致**（实测 1600/1280/1000/844/820/390/360 各档宽高比下卡高、卡宽均唯一）：
    任务名与进度都单行省略号截断、进度行即使无内容也占位（空闲机器填「最近结束 …」）、
    读数格子写死行高（标签 15px + 值 18px）。**卡片高度不能由内容撑**——只要有一张卡多折一行，整行卡片就会被拉高、网格参差不齐
- **状态口径**（由运行记录推断，前端 `bsBuild` 实现，与后端原 `dashboard.build_bot_status` 逐行对照移植）：有 `end` 为空且 `Executing` 的记录 = 运行中；无运行中但有在途记录 = 排队中；没有任何在途记录 = 空闲
- 卡片读数：空闲 / 近 24 小时 / 近 7 天 / 失败率 / 平均排队 / 平均运行
  - 「当前任务」= 在途任务名 + 已跑时长 / 排队时长（**点击直达该条记录日志**），多个在途时追加「另有 N 个在途」；
    无在途任务时标签变为「最近任务」并显示「最近：<应用名>」
  - 近 7 天失败率 ≥20% 标红；近 24h 失败数用「· 失败 N」追加在次数后
  - 卡片内时长一律用紧凑写法（`fmtDurShort`：「7分30秒」），一行 3 张时读数格子窄，带空格的写法会折行
- **标题栏指标卡**：机器人 / 运行中 / 排队中 / 空闲 / 在途任务（工具条里原来那句「共 N 台 · 运行中 …」的长文字已换成卡片，工具条只留数据时刻）
- 筛选：全部 / 仅忙（运行中 + 排队中）/ 仅空闲；**数据从本地记录现算**，记录随全局 SSE 链路更新后自动重渲染（不再有 `/api/botstatus` 接口与独立轮询）

## 手机端适配
桌面端与手机端是**互斥的两套布局逻辑**，断点统一取 `880px`（`mobile.css`、`theme.js`、
`app.js` 的 `MOBILE_Q` / `IS_MOBILE` 三处保持一致）：

| | 桌面端（>880px） | 手机端（≤880px） |
|---|---|---|
| 策略 | 禁止原生滚动条，内容压进一屏 | 自然文档流，整页纵向滚动（允许出现滚动条） |
| 缩放 | `theme.js` 写 `--s`，`.app` 等比缩放 | `--s` 归 1，`transform: none` |
| 左栏 | 214px 竖排固定栏 | 吸顶：品牌 + 数据时间 / 横向 tab（导航可直接点） |
| 指标卡 | 一行横排 | 每行两张（`box-sizing: border-box` + `calc(50% - 6px)`） |
| 图表 | 由 flex 分配剩余高度 | 时间轴整块不渲染（见下）；其他视图固定高度 |
| 宽表格 | 列自适应压缩 | 内容宽度 `max-content`，容器内横向滚动 |
| 机器人状态卡片 | 横屏一行 3 张，容器内往下滚 | 竖屏一行 1 张；容器不封顶，滚动交给整页 |
| 任务时间轴 | 甘特图 + 筛选卡 + 六列表格 | **只有记录流**：倒序、大号时长、滚到底续批，不横向滚动 |

实现要点：

- **`web/mobile.css` 是唯一的手机端布局层**，只在 `@media (max-width: 880px)` 内生效；
  删除 `index.html` 里这一行引用即可整体回退到桌面那套窄屏表现。
- **`web/theme.js`** 在断点两侧切换 `--s`（手机端归 1，避免与 `mobile.css` 打架），
  并把判定结果写到 `html[data-layout="mobile|desktop"]` 便于调试；跨断点自动重算。
- **`web/app.js`** 用 `IS_MOBILE` 分流 ECharts / Monaco 里 CSS 管不到的部分：
  运行记录（记录流 vs 表格）、热力图刻度 11→9px、排期图块文字 20→11px、
  手机端关闭 Monaco 缩略图（minimap）。
- **时间轴两端是两套东西**：手机端不建 ECharts 实例（`tlInit` 在 `IS_MOBILE` 时直接返回），
  甘特图卡片与筛选卡片靠 CSS `display: none` 隐藏。跨断点用 `applyTimelineLayout()` 整体换：
  切到桌面要**补建**图表实例，切到手机要 **`dispose()` 拆掉** —— 只 resize 是不行的，
  因为手机端根本没有实例。已实测反复来回切换都正常。
- **运行记录的两个容器共存**：`#tlListTbl`（表格）与 `#tlCards`（记录流）都在 DOM 里，
  由 `tlListRender` 按断点切显隐。两者**不能互相写 `innerHTML`** —— 那会把对方的元素
  连同容器一起抹掉，之后再也渲染不出来（切回手机就只剩空列表）。点击用事件委托挂在
  `#tlList` 上，同时匹配 `tr[data-rid]` 与 `.tl-card-item[data-rid]`。
- **手机端「更新不跳位」的判断依据是 `window.scrollY < 80`**：在顶部就重排（用户看得见新内容），
  滚下去了就只浮药丸、DOM 一律不动。列表渲染前的签名比对（`FEED.sig` = 条数 + 各条 id）
  用来区分「真变了」和「只是进行中的时长在走」，后者只改文本。
- **ECharts custom series 的两个坑**（都踩过）：
  `value` 数组前两位是 x/y 维度，附加数据要从 `value(2)` 起取，**文字塞在第 2 位会被当成
  y 轴时间值直接变成空**；且 `value` 会被按维度摊平，**嵌套数组会被摊成 `null`** ——
  要传多个值就摊平放成多个维度，别塞数组。
- 布局层的两条坑（都已修）：flex 子项同时有百分比基准和 padding 时必须配
  `box-sizing: border-box`，否则两张「半宽」卡片永远排不进一行；不能给
  `#logbox`（Monaco 宿主）随手写 `flex: none`，那会让宽度退化成 7px 的竖线。

## 飞书配置中心

项目配置统一存放在飞书多维表格「rpa_config」（`config.json` 的 `feishu.app_token` / `table_id` 指定），表字段：

| 字段 | 说明 |
|---|---|
| `key` | 配置项短名，仅允许 `字母数字._-` |
| `value` | 配置值，一律以字符串存储，按 type 解析 |
| `type` | `string` / `number` / `bool` / `json` |
| `group` | 配置分组；`project` 组存项目↔配置组映射（key=`p.<flowId>`，value=配置组名） |
| `desc` | 说明（保存时自动去换行） |

读写封装在 `feishu_cfg.py`：`get_group_items` / `get_group_config` / `upsert_item` / `delete_item`；服务端接口为 `/api/projects/config`。

## 数据更新机制

| 调度 | 频率 | 内容 |
|---|---|---|
| 运行记录轮询 | 每 6 秒（服务常驻，与有没有人打开页面无关） | 桌面 API runningRecords 最新 50 条逐行幂等 upsert 入库（在途+终态一次同步）；**只有真有行变化**才广播（重放同样的数据不算，无变化零广播） |
| 触发器排期轮询 | 每 12 小时 + 启动时一轮 | 网页版抓触发器排期入库；有变更才广播 |
| 排期「立刻更新」 | 手动（排期页按钮） | 不等下一轮，立刻抓取触发器并写库，抓完才返回；期间页面显示转圈提示 |
| 前端拉取 | SSE 事件驱动（始终开启，无开关） | 收到 `change` 就带游标增量拉取；排期页打开时拉一次排期 |

- 登录态失效不用人工干预：`octo_api` 遇 401 会把缓存 token 标死并**当场重新登录**、强制重取企业 ID 后重试原请求（约 1~2 秒恢复），不等下一个轮询周期；`crawler.py` 侧则由 `authenticate()` 自动用账号密码重登。
- 运行记录与排期的抓取通过 `UPDATE_LOCK` 互斥，不会并发写库。
- 排期抓取失败会写 `output/update_log.txt`，接口如实返回 `ok=false`（排期页会弹提示），不会误报成功。

## 手动执行

```bash
python crawler.py --config config.json --out output                            # 全量抓取（触发器 + 运行记录，都入库）
python crawler.py --config config.json --out output --only-triggers            # 仅抓触发器排期入库（排期页「立刻更新」走这条）
python crawler.py --config config.json --out output --only-runs                # 仅刷新运行记录（全量）
python crawler.py --config config.json --out output --only-runs --days 7       # 可选：只保留最近 7 天
python organize.py --input output\triggers_normalized.csv --out output         # 整理时刻表（可选，产出 md/xlsx 快照）
python local_server.py                                                          # 启动服务器（数据更新由内部线程自动跑）
```

> `dashboard.py` 是数据聚合模块，直接执行只打印提示，不再生成任何 HTML。
> 排期页与 Excel 导出都读数据库 `rpa_triggers` 表，`triggers_normalized.csv` 只作为离线快照保留。

## 配置

### `config.json`

> ⚠️ 含登录凭据，已在 `.gitignore` 中排除；首次使用请复制 `config.example.json` 并填入。

| 字段 | 说明 |
|---|---|
| `account.username / password` | 八爪鱼 RPA 登录邮箱/手机号 + 密码（自动登录，令牌缓存到 `output/octo_token.json`，会话缓存到 `output/session.json`） |
| `cookie` | 备用：浏览器登录后 F12 → `document.cookie` 填入 |
| `enterprise_id` | 可选：指定企业 ID；留空则默认选账号下第一个非个人企业 |
| `include_robots` | 只保留名称以这些前缀开头的机器人（如 `["A", "B"]` 或 `["A🍩硕晞-", "B💎宝实-"]`） |
| `exclude_robots` | 排除名称含这些关键词的机器人（如 `["测试"]`） |
| `feishu.app_id / app_secret` | 飞书自建应用凭据（项目控制台读/写配置中心用） |
| `feishu.app_token / table_id` | 飞书多维表格「rpa_config」配置中心表 |
| `access_password` | 可选：仪表盘访问密码（启用 Cookie 鉴权，空则不启用） |
| `robot_logs` | 机器人 → 局域网日志共享目录（UNC）白名单，详见下节 |

> **登录态过期自动恢复**：请求遇 401 时 `octo_api` 会把缓存 token 标死（时间窗判断不可靠，靠 401 现场反馈），当场重新登录、强制重取企业 ID 后重试原请求，约 1~2 秒恢复，不等下一个轮询周期；爬虫侧会话过期会删除缓存并改用 `account` 的账号密码重登（因此请务必在 `config.json` 中填好账号密码，而不仅依赖 cookie）。

### `robot_logs` 段

机器人 → 局域网日志共享目录（UNC）白名单，详情页只在这些根目录内检索，防止任意文件读取。键须与运行记录里的 `bot_name` 完全一致：

```json
"robot_logs": {
  "_说明": "键为机器人名，值为该机器人电脑共享出来的日志根目录 UNC 路径",
  "A🍩硕晞-01": "\\\\SX-01\\Logs",
  "B💎宝实-00": "\\\\BS-00\\Logs"
}
```

以 `_` 开头的键视为注释，不会加入白名单。
